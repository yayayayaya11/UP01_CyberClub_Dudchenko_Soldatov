## Сценарий демонстрации на 7–10 минут

1. Откройте SSMS, подключитесь к `(localdb)\MSSQLLocalDB` и покажите базу `DB_Dudchenko_Soldatov_CyberClub` и восемь таблиц. Установочный скрипт повторно выполнять не нужно.
2. Запустите `CyberClub.exe`. Три раза введите неверный пароль admin: появится капча. Введите правильную капчу и пароль `CyberAdmin1`.
3. Откройте «Компьютеры»: найдите VIP, примените фильтр «Статус → Ремонт», затем сбросьте фильтр и отсортируйте номера по убыванию.
4. Создайте клуб «Демонстрация», зону и компьютер. Создайте клиента и тариф. В формах внешние ключи выбираются по названиям.
5. Создайте бронь на этот компьютер с 12:00 до 14:00 выбранного свободного дня. При тарифе 150 руб./час стоимость составит 300 руб. Создайте второй пересекающийся интервал: программа должна его отклонить.
6. Внесите платёж 100 руб. Попытка добавить ещё 300 руб. будет отклонена как переплата. Сумма всех платежей не должна превышать 300 руб.
7. Отредактируйте данные и покажите сообщение успешного сохранения. Нажмите удаление созданного клуба и прочитайте предупреждение о каскаде. При подтверждении удалятся его зоны, компьютеры, брони и платежи. Демонстрационного клиента и тариф можно удалить отдельно.
8. Откройте диаграммы. Постройте выручку за октябрь 2026 года, смените столбцы на круговую диаграмму. Экспортируйте DOCX, PDF и XLSX в отдельные файлы.
9. Смените тему, выйдите из аккаунта, проверьте сохранение темы. Войдите как `user` / `CyberUser1`: кнопок изменения, диаграмм и экспорта нет.
10. Покажите регистрацию и смену пароля на отдельном демонстрационном аккаунте. Не меняйте учебные пароли admin и user перед защитой, если не обновляете инструкцию.

## Как устроен код

| Класс | Что объяснить |
|---|---|
| Program | Создаёт WPF Application и главное окно. Ошибки показываются пользователю. |
| CyberClubModel.edmx | Содержит модель из 8 сущностей, структуру SQL Server, соответствие полей и диаграмму связей. Это Database First, Code First не используется. |
| CyberClubEntities | Типизированный DbContext Entity Framework 6: Users, Clients, Clubs, Zones, Computers, Tariffs, Bookings, Payments. Модель загружается из встроенных CSDL/SSDL/MSL. |
| Core | Статическое поле Context содержит общий CyberClubEntities. LINQ и CRUD используют Core.Context; Query и Scalar выполняют выборки через его соединение. SaveChanges сохраняет изменения и очищает отслеживание. Контекст освобождается при выходе. |
| Account | Содержит Id, логин, ФИО, роль текущего пользователя и вычисляемое свойство IsAdmin. |
| Passwords | Validate проверяет формат; Hash создаёт соль и PBKDF2; Verify повторяет вычисление с сохранённой солью и сравнивает результат. |
| AuthService | Login считает ошибки и проверяет капчу; Register создаёт только пользователя; ChangePassword проверяет старый пароль; Logout очищает текущий аккаунт. |
| Catalog | Описывает восемь сущностей и поля форм. Lookup возвращает пары идентификатор–подпись для связанных объектов. |
| ClubService | Проверяет роль перед изменением; Parse проверяет смысл полей; Save добавляет или меняет сущность и вызывает SaveChanges; Delete использует Remove и SaveChanges; Revenue считает выручку. |
| MainWindow | ShowLogin, ShowRegistration и ShowPassword строят страницы входа. ShowData показывает таблицу; ApplyFilters выполняет поиск, фильтр и сортировку. ShowEditor строит форму по каталогу. |
| SetTheme | Меняет словари ресурсов и записывает выбранную тему в theme.txt. |
| DrawChart | Рисует столбцы или круговые сектора по суммам из БД. |
| Notify / Confirm | Единые WPF-диалоги сообщений и подтверждения. |
| Exporter | Word и Excel формируют Open XML ZIP-пакеты; Pdf строит страницы и записывает PDF с изображениями таблицы. |

## Короткие ответы на вопросы

**Почему 8 таблиц?** Каждая отвечает за отдельную сущность предметной области; размер соответствует совместному заданию двух студентов.

**Почему Users отдельно от Clients?** Учётная запись нужна для входа в программу. Клиент клуба может быть зарегистрирован администратором и не иметь аккаунта программы.

**Что такое PK и FK?** PK однозначно определяет строку. FK связывает строку с существующей строкой другой таблицы и не допускает «висячих» ссылок.

**Почему цена хранится и в тарифе, и в бронировании?** В тарифе хранится текущая цена, в брони — цена конкретной сделки. Повышение тарифа не должно менять уже оформленную бронь.

**Как считается стоимость?** `ROUND(число минут / 60.0 × цена часа, 2)`. Столбец Total вычисляет SQL Server.

**Как запрещаются пересечения?** Для одного компьютера интервалы пересекаются, если начало первой брони меньше конца второй и начало второй меньше конца первой. Отменённые брони не учитываются. Проверка находится в триггере и действует также при работе через SSMS.

**Зачем decimal?** Для денежных сумм с фиксированной точностью до копеек. Он не даёт ошибок двоичного округления, характерных для double.

**Что делает каскад?** Удаляет зависимые записи. В этой учебной работе это обязательное требование; в рабочей финансовой системе вместо удаления истории чаще используют архивирование.

**Зачем соль?** Одинаковые пароли имеют разные хэши. Итерации PBKDF2 замедляют подбор. Соль хранится рядом с хэшем и не является секретом.

**Где контролируются роли?** И в интерфейсе, и в ClubService.RequireAdmin. Скрытие кнопок само по себе не заменяет проверку операции.

**Как защищён ввод SQL?** Пользовательские значения передаются как параметры, а имена таблиц выбраны из фиксированного каталога.

**Как подключена БД?** Через ADO.NET Entity Data Model в файле Models/CyberClubModel.edmx. Контекст CyberClubEntities использует именованное подключение из App.config. LINQ читает типизированные сущности, а SaveChanges сохраняет изменения. Диаграмму можно открыть двойным щелчком по EDMX в Visual Studio.

**Считается ли стоимость брони выручкой?** Нет. Диаграммы суммируют Payments.Amount, то есть фактические оплаты за период.

**Что не нужно устанавливать для экспорта?** Word, Excel и дополнительные NuGet-пакеты. Форматы создаются кодом. PDF растровый, DOCX и XLSX редактируемые.

**Почему формы строятся программно?** Разделы имеют один типичный набор действий. Общий механизм уменьшает дублирование и сохраняет одинаковое поведение восьми таблиц. Главное окно и ресурсы описаны XAML.
