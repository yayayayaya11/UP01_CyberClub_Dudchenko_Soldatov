# CyberClub

Учебная практика УП.01.01. Тема: проектирование и разработка базы данных для управления сетью киберспортивных клубов.

Авторы: Дудченко Р.А. и Солдатов А.С. Группа: **4ИСИП-123**. Руководитель: Аксёнова Т.Г.

## Запуск на этом ПК

1. Откройте `CyberClub.exe` из этой папки. Не переносите EXE отдельно от ресурсов.
2. Войдите под одним из учебных аккаунтов:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | admin | CyberAdmin1 |
| Пользователь | user | CyberUser1 |

База **DB_Dudchenko_Soldatov_CyberClub** уже создана на **(localdb)\MSSQLLocalDB**. Подключение выполнено через **ADO.NET Entity Data Model (.edmx), Entity Framework 6.4.4, Database First**. Используется проверка подлинности Windows. Пароли приведены только для учебных аккаунтов.

Модель: `Models/CyberClubModel.edmx`. Контекст: `CyberClubEntities`. Строка подключения `CyberClubEntities` находится в `App.config`. Все восемь таблиц представлены классами и DbSet; авторизация использует LINQ, регистрация и CRUD — сущности и `SaveChanges()`. Подробности: `docs/Подключение_EDMX.md`.

## Возможности

- Просмотр всех 8 разделов; пользователь видит только собственную запись в разделе учётных записей.
- Поиск по отображаемым столбцам, точный фильтр по выбранному столбцу, сортировка в обоих направлениях.
- Добавление, редактирование и каскадное удаление всех восьми сущностей администратором.
- Авторизация, регистрация, смена пароля, две роли; PBKDF2-HMAC-SHA256 со случайной солью.
- Капча после трёх ошибок входа; она обязательна и при правильном пароле, пока не пройдена.
- Проверки полей, диапазонов, уникальности, времени бронирования, пересечений и суммы оплаты.
- Столбчатая и круговая диаграммы выручки с выбором клуба и периода.
- Экспорт отображаемых данных и аналитики в DOCX, PDF и XLSX.
- Светлая и тёмная темы, сохранение выбора, подсказки, плейсхолдеры, подтверждение выхода и удаления.

## Состав БД

Users, Clients, Clubs, Zones, Computers, Tariffs, Bookings, Payments — ровно восемь таблиц. Шесть внешних ключей настроены с `ON DELETE CASCADE`. Таблица Users содержит учётные записи приложения; Clients — клиентов клубов. Цена часа в бронировании фиксируется отдельно от текущего тарифа. Стоимость вычисляется SQL Server по минутам.

Учебный набор: 2 учётные записи, 10 клиентов, 3 клуба, 6 зон, 18 компьютеров, 4 тарифа, 12 бронирований и 10 платежей. Общая фактическая выручка — 3030 руб.

## Перенос на другой ПК

Нужны Windows, .NET Framework 4.8 и SQL Server LocalDB. Entity Framework 6.4.4 и провайдер SQL Server включены в комплект, скачивать пакеты для запуска не требуется. Microsoft Office для работы приложения не нужен.

1. Скопируйте всю папку проекта.
2. В SSMS подключитесь к `(localdb)\MSSQLLocalDB`.
3. Откройте `db/install.sql` и выполните один раз для новой учебной базы. Не выполняйте установочный скрипт над уже заполненной базой.
4. Запустите `CyberClub.exe`.

Строка подключения задана в `App.config`, секция `connectionStrings`, имя `CyberClubEntities`, провайдер `System.Data.EntityClient`. Если имя экземпляра изменится, измените `data source` внутри `provider connection string`. Для готового EXE правится `CyberClub.exe.config`; при сборке Visual Studio копирует App.config автоматически. Для резервного переноса исходные SQL-скрипты не требуют наличия файлов MDF из профиля Windows.

## Сборка

Откройте `CyberClub.sln` в Visual Studio с инструментами разработки .NET Framework 4.8 и выполните сборку. Альтернатива — `build.ps1`: он использует системный компилятор C# и сборки WPF, без загрузки зависимостей. Из PowerShell в папке проекта:

```powershell
./build.ps1
```

Скрипт создаёт `CyberClub.exe` и `Verify.exe`, извлекает метаданные CSDL/SSDL/MSL из EDMX и встраивает их в сборку. Решение Visual Studio использует стандартное действие `EntityDeploy` и собирает основное приложение в `bin/Debug` или `bin/Release`; ресурсы, конфигурация и DLL Entity Framework копируются автоматически. Пакет 6.4.4 уже находится в каталоге packages.

## Проверка

Запустите `Verify.exe`. Он создаёт отдельную временную БД с уникальным суффиксом, выполняет 20 проверок, снимает состояния интерфейса, проверяет экспорт и удаляет только свою временную базу. Основные учебные записи остаются на месте. Во время визуальной проверки на экране кратковременно открывается приложение; после окончания оно закрывается.

Результат: `tests/results/verification.txt`. Последний выполненный прогон: **20 пройдено, 0 ошибок**. Для повторной проверки нужны права текущего владельца LocalDB на создание тестовой базы. Переключение темы в проверочном режиме возвращает светлую тему в `theme.txt`.

## Особенности учебной реализации

Капча ограничивает повторные попытки внутри одного запущенного процесса. Это локальная учебная программа, а не серверная система с сетевым входом. Права ролей реализованы в приложении; владелец LocalDB имеет прямой административный доступ к своей базе через SSMS.

PDF-экспорт содержит растровые страницы с кириллицей; он пригоден для просмотра и печати, но текст не копируется. DOCX и XLSX содержат редактируемый текст и числовые значения. Поле Photo хранит необязательный локальный путь; отдельная галерея фотографий не предусмотрена.
